# ops-support Part 2: MCP Server — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `ops-mcp` in its MVP mode, `operational-support`: a stdio MCP server whose tools let a client go from a problem statement to a root cause and proposed fix: graph and code navigation, logs from compose/Kubernetes/files mapped to code, configuration checks, read-only PostgreSQL and Redis access, LSP lookups, and agent playbooks as MCP prompts.

**Architecture:**
- Tool logic lives in `engine` modules (`logs`, `logmatch`, `cfgcheck`, `datastore`, `lsp`) so it can be tested without MCP.
- `services/mcp` is a thin `rmcp` 3.7 adapter: one struct `OpsServer { root: PathBuf }` with `#[tool_router]` and `#[prompt_router]`.
- Each tool call reloads `Ctx` (so config edits apply live), connects to whatever backend it needs, and returns JSON text. Every output passes through `redact`.

**Tech Stack:** rmcp 3.7 (features `server`, `transport-io`, `macros`; use `rmcp::schemars`), tokio, sqlx 0.9 (`runtime-tokio`, `tls-rustls`, `postgres`, `json`), redis 1.8 (`tokio-comp`), `kubectl` and `docker` CLIs as subprocesses, plus everything from Part 1.

**Spec:** `docs/superpowers/specs/2026-10-24-ops-support-design.md` · **Depends on:** `docs/superpowers/plans/2026-10-24-ops-indexer.md` (Tasks 0–7)

## Global Constraints
- Tools return `Result<String, String>`. `Ok` is pretty JSON. `Err` is a one-line redacted message. A tool never panics.
- The server starts and answers `tools/list` with Memgraph, Postgres, Redis, Docker and kubectl all unavailable.
- Output caps: logs 2,000 lines / 256 KiB per call; SQL 200 rows; Redis values 4 KiB each; `read_file` 400 lines; `graph_query` 500 records.
- Arguments from the LLM are never interpolated into a shell. Subprocesses use argv (`tokio::process::Command`), and placeholders replace whole arguments.
- `since` accepts `^\d+[smhd]$`, capped at `7d`.
- Kubernetes namespaces must be in `kubernetes.namespaces`. Anything else is rejected before `kubectl` runs.
- **Modes:** `ops-mcp --mode <mode>`. This plan implements `operational-support` only, and it is the default. Every tool and prompt in this plan belongs to that mode. The spec's other modes (`developer-support`, `operational-onboarding`, `developer-onboarding`) are out of scope here, and their names are rejected with "mode not available yet".
- `ops-mcp` writes nothing to stdout but MCP protocol messages. Every tool runs through `run_tool` (Task 8a), so it is audited.
- Tool names and parameters are exactly as written in this plan. Each tool's description says what it returns and when to use it.

## Review Focus
1. **Backends down at startup.** The server must still list all tools, and a tool call must return an error string, not crash. Test: `smoke_lists_tools_with_backends_down` (Task 8).
2. **Secrets in errors.** A Postgres connection failure must not echo the URL's password. A compose `environment` containing `PASSWORD=` must come back masked from `service_config`. Tests: `pg_error_has_no_password` (Task 12), `service_config_redacts` (Task 11).
3. **Write attempts through read tools:** `WITH d AS (DELETE …) SELECT 1`, `SELECT 1; DROP TABLE x`, lowercase `merge (n)` in Cypher, `CALL` procedures, Redis `FLUSHALL`/`CONFIG SET`/`EVAL`. Tests: `pg_rejects_writes` (Task 12, ignored), `cypher_guard` (Task 8), `redis_allowlist` (Task 12).
4. **Multi-line Python tracebacks** must map to the function and line that raised. They must not become dozens of unmatched lines. Test: `traceback_frames_resolve` (Task 10).
5. **A log directory that isn't writable**, or a client that never sends `logging/setLevel`, must not break tool calls or put log text on stdout. Test: `logging_never_breaks_protocol` (Task 8a).
6. **Namespace outside the allow-list**, or a `since` like `1m; rm -rf /`, must be rejected before any process starts. Test: `k8s_namespace_and_since_rejected` (Task 9).

  - `audit::AuditRecord { ts, session_id, client: Option<ClientInfo>, tool, args: Value, outcome: &'static str, error: Option<String>, duration_ms: u64, backends: Vec<String>, result: ResultMeta { bytes: usize, rows: Option<usize>, lines: Option<usize>, truncated: bool } }`

Writing is append-only JSONL to `<dir>/audit.YYYY-MM-DD.jsonl`, behind one `Mutex<File>` reopened when the date changes. It's a no-op when `audit: false`. `// ponytail: one mutex-guarded file; move to a channel writer if tool calls ever run in parallel at volume`.

    - backend unreachable (warn);
    - a cap hit (warn: "rows truncated at 200");
    - a rejected namespace or command (warn).

### Task 10: `match_log` and `analyze_logs`

**Files:**
- Create: `services/engine/src/logmatch.rs`
- Modify: `services/mcp/src/server.rs`

**Interfaces:**
- Consumes: `store::query_async` (loads `LogStatement {id, regex, level, service, file}` plus `(f)-[:LOGS]->` function id), `logs::fetch`, `codeq::trace_flow`
- Produces:
  - `logmatch::Template { id, function_id, service, level, template, regex: Regex, literal_len: usize }`
  - `logmatch::best_match<'a>(tpls: &'a [Template], line: &str, service: Option<&str>) -> Option<&'a Template>`: prefers the given service, then the longest `literal_len`.

### Task 11: `service_config` and `check_config`

**Files:**
- Create: `services/engine/src/cfgcheck.rs`
- Modify: `services/mcp/src/server.rs`

**Interfaces:**
- Consumes: `Ctx`, `docker::load_compose`, `docker::parse_dockerfile`, `store::query_async` (READS_ENV per service), `runtime::k8s_status` pod env names
- Produces:
  - `cfgcheck::Finding { severity: "error"|"warn", service: String, kind: String, detail: String, location: Option<String> /* "file:line" from compose/Dockerfile spans */ }`. `kind` is one of `missing_env`, `unused_env`, `unresolved_secret`, `dangling_depends_on`, `port_mismatch`, `datastore_unreachable_host`, `no_logs_source`.
  - `cfgcheck::check(ctx: &Ctx, reads: &HashMap<String, BTreeSet<String>> /* service → env names read in code */, k8s_env: Option<&HashMap<String, BTreeSet<String>>>) -> Vec<Finding>`. Pure, given its inputs.
    - **missing_env:** the code reads a var that no compose env, env_file, Dockerfile ENV, `.env` or k8s env sets. Error, unless the read has a default. Task 4 records reads with a default as `"X?"`; strip the `?` and downgrade to warn.
    - **port_mismatch:** the Dockerfile `EXPOSE` port isn't the container side of any compose `ports` mapping.

    - Allow-list: `GET MGET EXISTS TYPE TTL PTTL STRLEN HGET HMGET HGETALL HKEYS HLEN LRANGE LLEN LINDEX SMEMBERS SCARD SISMEMBER ZRANGE ZRANGEBYSCORE ZCARD ZSCORE XRANGE XREVRANGE XLEN XINFO SCAN HSCAN SSCAN ZSCAN INFO DBSIZE PING`.

    - `SCAN … COUNT` is capped at 1000.
  - `datastore::redis_command(url, cmd, args) -> Result<Value>` (values truncated to 4 KiB, then redacted) and `datastore::redis_health(url) -> Result<Value>` (an INFO subset: version, uptime, connected_clients, used_memory_human, maxmemory_policy, evicted_keys, rejected_connections, role, keyspace).
